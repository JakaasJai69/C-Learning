# Constant Expressions and Constant Initilizer

Bascially there are two ways compiler can evaluate the expressions and initlizers in a program:

1. At Runtime
2. At Compiletime

These are done to improve the performance, make size shorter and optimize etc. for a program.

To determine, if an expression will be an Runtime or Compiletime we need to know that it is not necessary compiler will otimize it depends upon arch, cpu, version etc.

Now if the parts of expression are all constant, then the expression is constant:
ex- (20.12 * "5" + 2)

and an initlizer can be optimized for constnt if the expression inside is constant, but it is not always true.

ex: int test{5}; // can be optimized or not depending on compiler

but const int test{5}; is always constant due to constant prefix, note that const only works for integer expression.

but const double test{5.5}; is not const.

but constexpr double test{5.5}; is const due to constexpr prefix, it works for everything.

for functions, the return typemust be prefixed wirh const for integer or constexpr for others.

```cpp
#include <iostream>

int max(int x, int y) // this is a non-constexpr function
{
    if (x > y)
        return x;
    else
        return y;
}

constexpr int cmax(int x, int y) // this is a constexpr function
{
    if (x > y)
        return x;
    else
        return y;
}

int main()
{
    int m1 { max(5, 6) };            // ok
    const int m2 { max(5, 6) };      // ok
    constexpr int m3 { max(5, 6) };  // compile error: max(5, 6) not a constant expression

    int m4 { cmax(5, 6) };           // ok: may evaluate at compile-time or runtime
    const int m5 { cmax(5, 6) };     // ok: may evaluate at compile-time or runtime
    constexpr int m6 { cmax(5, 6) }; // okay: must evaluate at compile-time

    return 0;
}

```
